# PMO Builder (pmotools-app v1.2.0, submodule a0fd6fa) page inventory

Source: [pmotools-app](https://github.com/PlasmoGenEpi/pmotools-app) at a0fd6fa. pmotools v1.2.2.
Alias config: `conf/schema.json` (not a JSON Schema; it lists PMO field names and aliases per section: 129 field names, 412 aliases).

## Shared upload-and-map flow (`src/field_matcher.py::load_data`), used by every table upload

1. File uploader. Accepts csv, tsv, txt, xlsx, xls, gz, gzip. The label always reads "Upload a TSV file".
2. If the file is .xlsx or .xls and has more than one sheet, the user picks a sheet in a selectbox.
3. `load_csv`:
   - .csv, .tsv, .txt: `pd.read_csv(sep=None, engine="python")`, which sniffs the delimiter with csv.Sniffer. Encoding is UTF-8 only; no encoding fallback.
   - .gz: gunzip, then the same read, as UTF-8.
   - .xlsx: `pd.read_excel(sheet_name)` through openpyxl.
   - .xls: accepted but fails at runtime because xlrd is not installed.
   - pandas infers column types: numeric columns become int or float, empty cells become NaN, leading zeros are lost.
4. "Preview File" toggle shows `st.dataframe(df)`.
5. Required-field matching (`fuzzy_match_fields`, `is_required=True`):
   - Pass 1 is a case-insensitive exact match against the target name, then against its aliases in list order.
   - Pass 2 runs `fuzzywuzzy.process.extractOne(target, remaining)` with the default scorer (WRatio) and the default processor (full_process). It also runs extractOne on each alias and keeps the highest score.
   - A required field always takes its best match, whatever the score. Matching is greedy in schema order, and a matched column is removed from the pool.
   - It shows an error if there are fewer unique columns than required fields.
6. Optional-field matching runs over the columns left after step 5, with `is_required=False`. A fuzzy match counts only if its score is at least 60. The selectboxes include a "no match" option.
7. "Manually Alter Field Mapping" toggle shows one selectbox per field, plus a "Set All to No Match" button for optional fields. If two fields map to the same column, the app shows `st.error`, but this does not block Transform.
8. "Additional Fields" shows a checkbox for each column that is still unmapped.
9. It returns `(df, required_map, optional_map, additional_cols)`.

The whole flow, including the file parse and the fuzzy match, re-runs on every widget interaction. Nothing is cached.

## Session-state contract between pages

- `panel_info`: dict. `microhaplotype_info`: dict.
- `specimen_info`, `library_sample_info`, `project_info`, `seq_info`, `bioinfo_methods_list`, `bioinfo_run_infos`, `read_counts_per_stage`: lists of dicts.
- `formatted_pmo`: dict.
- Data flowing between pages: library_sample_info supplies panel_name suggestions to page 1 and sequencing_info_name suggestions to page 6. microhaplotype_info supplies run-name pre-fill to page 7.
- None of this survives a page reload. Uploaded files and mapping widgets reset when the user navigates to another page; only the transformed results persist.
